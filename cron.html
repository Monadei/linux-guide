Cron и systemd timers

Запускать задачи по расписанию.

Cron

Классика. Работает везде. Управляется через crontab.

crontab -e   # редактировать свой
crontab -l   # показать
crontab -r   # удалить всё

Синтаксис

минута час день_месяца месяц день_недели команда
  • минута: 0–59
  • час: 0–23
  • день месяца: 1–31
  • месяц: 1–12
  • день недели: 0–7 (0 и 7 = воскресенье)

Примеры

# Каждый день в 3 утра
0 3 * * * /home/user/backup.sh

# Каждые 15 минут
*/15 * * * * /home/user/check.sh

# Каждый понедельник в 9 утра
0 9 * * 1 /home/user/report.sh

# Первое число каждого месяца
0 0 1 * * /home/user/monthly.sh

# Каждые 5 минут с 9 до 18 по будням
*/5 9-18 * * 1-5 /home/user/sync.sh

# Одновременно несколько значений
0 0 * * 1,3,5 /home/user/odd.sh

Специальные строки

@reboot  — при загрузке
@daily   — раз в день в полночь
@weekly  — раз в неделю
@monthly — раз в месяц
@yearly  — раз в год

Логи и переменные

SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin
MAILTO=monadei@example.com

0 3 * * * /home/user/backup.sh >> /home/user/backup.log 2>&1

Важно: cron использует **минимальное** окружение, не твоё из .bashrc. Всегда указывай полные пути и PATH.

systemd timers

Современный подход. Работает через юниты.

Пример: бэкап каждую ночь в 3:00.

~/.config/systemd/user/backup.service:

[Unit]
Description=Backup

[Service]
Type=oneshot
ExecStart=/home/user/backup.sh

~/.config/systemd/user/backup.timer:

[Unit]
Description=Daily backup

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target

Активировать:

systemctl --user daemon-reload
systemctl --user enable --now backup.timer
systemctl --user list-timers

Синтаксис OnCalendar

daily              # каждый день в 00:00
hourly             # каждый час
weekly             # раз в неделю
Mon..Fri 09:00     # по будням в 9 утра
*-*-1 03:00        # 1-го числа каждого месяца
*:0/15             # каждые 15 минут

Проверить:

systemd-analyze calendar "Mon..Fri 09:00"

Cron vs systemd timers

  • Cron — проще, работает везде, старая школа
  • systemd timers — логи через journalctl, зависимости, точнее работает после сна/выключения

Для простых задач — cron. Для сложных с зависимостями — systemd.

Мониторинг

journalctl -u backup.timer
journalctl -u backup.service
grep CRON /var/log/syslog

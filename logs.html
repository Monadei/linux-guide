Логи и journalctl

Куда смотреть, когда что-то сломалось.

journalctl — основной инструмент

journalctl                 # все логи
journalctl -b              # с последней загрузки
journalctl -b -1           # предыдущая загрузка
journalctl -f              # следить в реальном времени
journalctl -n 50           # последние 50 строк
journalctl -p err          # только ошибки
journalctl --since "1 hour ago"
journalctl --since "2026-09-19" --until "2026-09-20"

По юниту

journalctl -u nginx
journalctl -u ssh -f
journalctl -u docker --since today

По процессу или пользователю

journalctl _PID=1234
journalctl _UID=1000
journalctl _COMM=firefox

Уровни важности

  • 0 emerg — паника
  • 1 alert
  • 2 crit
  • 3 err — ошибки
  • 4 warning
  • 5 notice
  • 6 info
  • 7 debug
journalctl -p 3          # ошибки и выше
journalctl -p warning    # предупреждения и выше

Формат вывода

journalctl -o short        # по умолчанию
journalctl -o short-precise  # с микросекундами
journalctl -o json         # JSON
journalctl -o cat          # только сообщение
journalctl -o verbose      # все метаданные

Управление размером

journalctl --disk-usage
sudo journalctl --vacuum-size=500M
sudo journalctl --vacuum-time=2weeks

Конфиг: /etc/systemd/journald.conf:

SystemMaxUse=500M
MaxRetentionSec=2week

Применить:

sudo systemctl restart systemd-journald

Классические логи

/var/log/syslog      # системный (Debian/Ubuntu)
/var/log/messages    # системный (RHEL)
/var/log/auth.log    # авторизация
/var/log/kern.log    # ядро
/var/log/dpkg.log    # установка пакетов (Debian)
/var/log/apt/        # apt
/var/log/nginx/      # веб-сервер
/var/log/Xorg.0.log  # графика
tail -f /var/log/syslog
less /var/log/auth.log
grep "error" /var/log/syslog

logrotate

Автоматически ротирует и сжимает логи. Конфиги в /etc/logrotate.d/.

sudo logrotate -d /etc/logrotate.conf   # dry-run
sudo logrotate -f /etc/logrotate.conf   # применить

Что искать при проблемах

# Ошибки с последней загрузки
journalctl -p err -b

# Что не запустилось
systemctl --failed

# Что долго грузилось
systemd-analyze blame

# Кто упал
journalctl -b | grep -i "segfault\|panic\|failed"

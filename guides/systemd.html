Как устроен systemd

Что такое systemd, из чего состоит, почему его критикуют.

Что это

systemd — система инициализации (init). Первая программа, которую запускает ядро после загрузки. Дальше systemd запускает всё остальное: сервисы, таймеры, устройства.

Что входит в systemd

  • systemd — основной init (PID 1)
  • journald — логи (journalctl)
  • logind — управление сессиями
  • networkd — сеть
  • resolved — DNS
  • timedated — время и дата
  • udevd — устройства
  • bootctl — загрузчик systemd-boot
  • coredump — дампы падений
  • tmpfiles — временные файлы

Юниты

Юнит — единица конфигурации. Типы:

  • .service — сервис
  • .timer — таймер
  • .socket — сокет
  • .target — группа юнитов
  • .mount — точка монтирования
  • .device — устройство
  • .path — путь

Где лежат

/usr/lib/systemd/system/       # системные
/etc/systemd/system/           # пользовательские (перебивают системные)
~/.config/systemd/user/        # для текущего пользователя

Targets

Target — цель загрузки. Как runlevel в старых системах.

multi-user.target      # обычная система (без GUI)
graphical.target       # с графическим интерфейсом
rescue.target          # режим восстановления
emergency.target       # минимальный режим
reboot.target          # перезагрузка
poweroff.target        # выключение
systemctl get-default
sudo systemctl set-default multi-user.target

Основные команды

systemctl status сервис
systemctl start сервис
systemctl stop сервис
systemctl restart сервис
systemctl reload сервис
systemctl enable сервис
systemctl disable сервис
systemctl mask сервис              # запретить даже запуск
systemctl unmask сервис
systemctl list-units
systemctl list-units --failed
systemctl list-dependencies сервис

Свой сервис

# /etc/systemd/system/myapp.service
[Unit]
Description=My Application
After=network.target

[Service]
Type=simple
User=monadei
WorkingDirectory=/home/monadei/myapp
ExecStart=/usr/bin/python3 /home/monadei/myapp/main.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
sudo systemctl status myapp
journalctl -u myapp -f

Почему критикуют

  • Монолитность — делает слишком много всего
  • Не UNIX-way — «одна программа — одно дело» не соблюдается
  • Бинарные логи — journald хранит не в текстовом виде
  • Сложность — много концепций для новичка
  • Спорный лидер — Леннарт Поттеринг, автор systemd, не всем нравится

Альтернативы

  • OpenRC — Gentoo, Alpine, Artix
  • runit — Void Linux
  • s6 — Artix, некоторые embedded
  • dinit — Chimera Linux
  • sysvinit — Slackware, Devuan

Но: systemd победил. Fedora, Ubuntu, Debian, Arch, openSUSE, RHEL — все на нём. Если хочешь без systemd — Artix, Void, Alpine, Devuan.

Полезные команды

systemd-analyze                      # время загрузки
systemd-analyze blame                # что долго грузится
systemd-analyze critical-chain       # цепочка зависимостей
systemctl list-timers                # таймеры
systemd-cgls                         # дерево cgroups
loginctl list-sessions               # сессии
hostnamectl                          # инфо о системе
timedatectl                          # время
localectl                            # локаль

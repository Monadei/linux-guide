SELinux vs AppArmor

Мандатный доступ в Linux — что выбрать и почему.

Что общего

  • Оба — системы мандатного доступа (MAC)
  • Ограничивают, что может делать программа, даже если её взломали
  • Работают поверх обычных прав (chmod/chown)
  • Включены по умолчанию в большинстве дистрибутивов

Ключевое различие

SELinuxAppArmor
ПодходПо меткам (labels)По путям (paths)
СложностьВысокаяСредняя
Где по умолчаниюFedora, RHEL, CentOSUbuntu, SUSE, Debian
ГибкостьОчень гибкийПроще настроить
ДокументацияОгромная, но сложнаяПроще

SELinux — подробнее

Как работает: каждому файлу и процессу присваивается метка (контекст). Процесс может обратиться к файлу, только если его метка разрешена.

# Проверка
getenforce
sestatus

# Режимы
sudo setenforce 0   # Permissive
sudo setenforce 1   # Enforcing

# Контексты
ls -Z /var/www/
sudo chcon -t httpd_sys_content_t /var/www/html/file.html
sudo restorecon -Rv /var/www/

# Булевы значения
getsebool -a | grep httpd
sudo setsebool -P httpd_can_network_connect on

# Логи
sudo ausearch -m avc -ts recent
sudo sealert -a /var/log/audit/audit.log

AppArmor — подробнее

Как работает: каждому приложению — свой профиль. Профиль описывает, к каким путям и с какими правами приложение может обращаться.

# Проверка
sudo aa-status

# Профили
ls /etc/apparmor.d/

# Режимы
sudo aa-complain /usr/bin/firefox   # только логирует
sudo aa-enforce /usr/bin/firefox    # блокирует
sudo aa-disable /usr/bin/firefox    # отключить

# Логи
sudo journalctl -k | grep apparmor
sudo dmesg | grep apparmor

Когда что использовать

  • Fedora / RHEL / AlmaLinux / Rocky — SELinux. Он там по умолчанию, не трогай.
  • Ubuntu / Debian / SUSE — AppArmor. Тоже по умолчанию.
  • Свой сервер — что установлено в дистрибутиве.
  • Пентест — на Kali AppArmor, на RHEL — SELinux.

Что делать, если блокирует

AppArmor

# Временно — complain-режим
sudo aa-complain /usr/bin/программа

# Логи
sudo journalctl -k | grep apparmor

SELinux

# Временно — permissive
sudo setenforce 0

# Найти проблему
sudo ausearch -m avc -ts recent

# Логи
sudo sealert -a /var/log/audit/audit.log

Не отключай полностью

Многие отключают SELinux или AppArmor, когда что-то не работает. Это плохая идея. Лучше:

  1. Понять, что блокируется (логи)
  2. Разрешить конкретное действие (правило, булево значение)
  3. Или перевести в permissive-режим (логирует, но не блокирует)

Мандатный доступ — важная часть безопасности. Отключать его ради «чтобы работало» — как снимать замок с двери, потому что потерял ключ.

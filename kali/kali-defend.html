Защита Linux

Как защитить свою систему: firewall, SSH, SELinux, fail2ban. Чек-лист.

Обзор С чего начать Инструменты Практика Защита Linux

Зачем это знать

Пентест без понимания защиты — половина дела. Чтобы найти уязвимость, надо понимать, как её закрывают. Плюс — это твоя собственная система, её тоже надо защищать.

Я первым делом настроил защиту своего Ubuntu и MacBook. Понял: одно дело — уметь ломать, другое — не быть сломанным самому. Второе важнее.

Базовая гигиена

1. Обновления

# Ubuntu/Debian
sudo apt update && sudo apt upgrade -y

# Fedora
sudo dnf upgrade --refresh

# Автоматические обновления безопасности
sudo apt install unattended-upgrades
sudo dpkg-reconfigure unattended-upgrades

2. Firewall

# UFW (Ubuntu)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw enable
sudo ufw status verbose

3. SSH — самое важное

# Отключить вход по паролю
sudo nano /etc/ssh/sshd_config
# PasswordAuthentication no
# PermitRootLogin no
# Port 2222  # сменить порт

sudo systemctl restart ssh

Использовать только ключи ed25519:

ssh-keygen -t ed25519 -C "monadei@ubuntu"
ssh-copy-id user@server

4. fail2ban

Блокирует IP после нескольких неудачных попыток входа.

sudo apt install fail2ban
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd

Продвинутая защита

1. SELinux / AppArmor

Мандатный доступ — ограничивает, что может делать программа, даже если её взломали.

# AppArmor (Ubuntu)
sudo aa-status
sudo apt install apparmor-utils

# SELinux (Fedora, RHEL)
sestatus
sudo setenforce 1  # Enforcing

2. Аудит системы

# Lynis — аудит безопасности
sudo apt install lynis
sudo lynis audit system

# Покажет, что не так, и даст рекомендации

3. Мониторинг логов

# Подозрительные входы
journalctl -u ssh --since "1 hour ago" | grep -i failed

# Все sudo-команды
journalctl -t sudo

# Мониторинг в реальном времени
journalctl -f

4. Проверка портов

# Что слушает наружу
sudo ss -tulpn

# Проверить снаружи
nmap -sV localhost

# Закрыть ненужное
sudo systemctl stop ненужный_сервис
sudo systemctl disable ненужный_сервис

5. Шифрование

LUKS для диска при установке. Если система уже стоит — можно зашифровать только /home:

sudo apt install ecryptfs-utils
ecryptfs-migrate-home -u $USER

Особые случаи

Если ты на ноутбуке и часто в чужих Wi-Fi

  • VPN — всегда. Mullvad, ProtonVPN, WireGuard
  • Firewall — deny incoming по умолчанию
  • Отключи автоподключение к открытым сетям
  • DNS over HTTPS — Cloudflare 1.1.1.1 или Quad9

Если ты хостишь что-то публично

  • Reverse proxy — nginx/caddy перед приложением
  • HTTPS — Let's Encrypt, обязательно
  • Rate limiting — защита от брутфорса
  • WAF — ModSecurity или Cloudflare
  • Резервные копии — регулярно, на отдельный диск
  • Мониторинг — Netdata, Grafana

Если у тебя сервер с SSH

# Дополнительно к базовому:
# - Сменить порт с 22
# - Только ключи, никаких паролей
# - fail2ban с агрессивными настройками
# - SSH через WireGuard VPN (порт вообще закрыт наружу)
# - Port knocking (опционально)
На моём сервере порт 22 закрыт вообще. SSH работает только через WireGuard. За 6 месяцев — ни одной попытки брутфорса, потому что некуда стучаться.

Чек-лист безопасности

Проверь свою систему по этому списку:

Обязательное

  • ☐ Все обновления установлены
  • ☐ Firewall включён, deny incoming
  • ☐ SSH: ключи вместо паролей, root отключён
  • ☐ fail2ban работает
  • ☐ Пароли в менеджере (KeePassXC, Bitwarden)
  • ☐ 2FA на важных аккаунтах
  • ☐ Резервные копии настроены
  • ☐ Диск зашифрован (хотя бы /home)

Хорошо иметь

  • ☐ SELinux или AppArmor включён
  • ☐ Lynis аудит проведён
  • ☐ Логи мониторятся
  • ☐ VPN для публичных Wi-Fi
  • ☐ DNS over HTTPS
  • ☐ Отдельная сеть для IoT

Продвинутое

  • ☐ SSH через VPN
  • ☐ Port knocking
  • ☐ IDS/IPS (Suricata, Snort)
  • ☐ Мониторинг (Netdata, Wazuh)
  • ☐ Регулярный пентест своих систем
Не пытайся сделать всё сразу. Начни с обновлений, firewall и SSH-ключей. Это 80% защиты. Остальное — по мере необходимости.
